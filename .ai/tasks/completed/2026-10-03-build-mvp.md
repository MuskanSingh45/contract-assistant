# Build: Backend, AI, Frontend, Evaluation (2026-10-03, Claude + Claude agents + Codex)

## Built
- **Backend** (Codex first, then reviewed and reworked by Claude): FastAPI app, every endpoint in `docs/api/`, analysis background task, review/clarification/version services, recalculation. Added endpoints: `GET /api/reviews/recent`, `GET /api/items/{type}/{id}`. Added fields: `days_until_term_end`, `original_display_value`, `label`, `clarification_id`. All documented.
- **Date engine** (Claude agent): `backend/utils/dates.py` + 23 tests.
- **Parsers** (Claude agent): PDF/DOCX/TXT → segments + tests; demo PDF/DOCX samples.
- **AI pipeline** (Claude agent): Ollama client, windowing, two prompts (terms-v2, obligations-v2), validation, citation grounding, deterministic conflicts. About 2 min per contract with qwen3:8b.
- **Frontend** (Claude: foundation, contract detail, review queue, review item; Codex: dashboard, contracts, upload, analyzing, obligations, renewals, versions, summary, settings, help). Built from the product designs. Claude reviewed Codex's code and fixed about 15 issues. Verified in Chrome.
- **Integration tests** (Codex, reviewed by Claude): `tests/integration/`, 17 tests.
- **AI evaluation** (Claude): `scripts/evaluate_ai.py`, `ai/evaluation/`, 5 samples with fixtures.

## Bugs found and fixed
- The parser dropped short numbered clauses ("4.1 Client shall provide access.") as headings, losing contract text. The fix requires numbered headings to not end like a sentence and to be at most 8 words; regression test added.
- The review/item UI showed raw field names, wrong date sorting in Summary, and wrong citations on Renewals (see the frontend review notes in the session).
