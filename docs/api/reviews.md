# Reviews API

Two entity types can be reviewed: `extracted_item` and `obligation`. Renewals are
calculated, so they are not reviewed directly (see [renewals.md](renewals.md)).

## GET `/api/reviews/queue`

Drives the **Review** page. Returns items with `review_status = pending` from the latest
version of each contract. Items with `confidence = low`, a `not_found` citation, or an open
clarification come first.

| Param | Meaning |
|---|---|
| `contract_id` | Optional filter |
| `entity_type` | `extracted_item` or `obligation` |

Response `200`:

```json
{
  "items": [
    {
      "entity_type": "extracted_item",
      "entity_id": "itm_globex_notice_90",
      "contract_id": "ctr_globex",
      "contract_name": "Globex Hosting Agreement",
      "contract_version_id": "ver_globex_1",
      "field_name": "notice_period",
      "label": "Notice period",
      "display_value": "90 days before expiration (non-renewal)",
      "value": { "value": 90, "unit": "days", "anchor": "expiration_date", "purpose": "non_renewal" },
      "confidence": "medium",
      "review_status": "pending",
      "ambiguity_note": null,
      "clarification_id": "clq_globex_notice",
      "citations": [ /* Citation objects */ ]
    }
  ]
}
```

For obligations, `field_name` is `null`, `label` is `"Obligation"`, `display_value` is the description and `value` holds the editable fields.

Open clarification questions are listed separately by `GET /api/clarifications?status=open`.
The Review page shows them in a section above the queue.

## POST `/api/reviews`

Request:

```json
{
  "entity_type": "extracted_item",
  "entity_id": "itm_acme_notice",
  "action": "edit",
  "value": { "value": 60, "unit": "days", "anchor": "expiration_date", "purpose": "non_renewal" },
  "note": "Amended by side letter dated 2026-03-01"
}
```

| action | Effect | `value` |
|---|---|---|
| `approve` | `review_status → approved` | must be omitted |
| `edit` | replaces `value` (extracted item) or the content fields (obligation); `review_status → edited` | required. Extracted item: the full value shape for its `field_name` (see [contracts.md](contracts.md)). Obligation: any of `description`, `responsible_party`, `frequency`, `frequency_text`, `due_rule`, `due_date`. |
| `reject` | `review_status → rejected`; the item is excluded from calculations and summaries but kept in the database | must be omitted |

Rules:

- `original_value` is never modified. Edits only change `value`.
- Any action may be applied again (e.g. re-approve a rejected item). Every action appends to the history.
- If the item is an input to the renewal calculation, the backend recalculates the renewal and calculated obligation due dates **in the same request**.
- An action on an item inside an open clarification does not resolve the clarification. Use `POST /api/clarifications/{id}/resolve` for that.
- `display_value` is regenerated by the backend.

Response `200`:

```json
{
  "item": { /* updated extracted item or obligation object */ },
  "review": { /* Review history entry, see below */ },
  "renewal": { /* recalculated Renewal object, or null if not affected */ }
}
```

Errors: `ITEM_NOT_FOUND`, `INVALID_REVIEW_ACTION` (unknown action, `value` missing for edit
or present for approve/reject), `VALIDATION_ERROR` (edited value does not match the field's
shape, e.g. an invalid date).

## GET `/api/reviews`

History for one item. Query: `entity_type` and `entity_id` (both required).

Response `200`:

```json
{
  "items": [
    {
      "id": "rev_acme_eff",
      "entity_type": "extracted_item",
      "entity_id": "itm_acme_eff",
      "action": "approve",
      "previous_review_status": "pending",
      "new_review_status": "approved",
      "previous_value": null,
      "new_value": null,
      "note": null,
      "clarification_id": null,
      "reviewed_at": "2026-09-29T14:10:00Z"
    }
  ]
}
```

Newest first. `previous_value`/`new_value` are only set for `edit`.

## GET `/api/items/{entity_type}/{entity_id}`

One reviewable item with its context, for the review screen. `entity_type` is
`extracted_item` or `obligation`.

```json
{
  "entity_type": "extracted_item",
  "item": { /* extracted item (contracts.md) or obligation (obligations.md) */ },
  "contract_id": "ctr_acme",
  "contract_name": "Acme Services Agreement",
  "version_number": 1,
  "is_latest_version": true
}
```

Error: `ITEM_NOT_FOUND`.

## GET `/api/reviews/recent`

The latest review actions across all contracts, for "Recently reviewed" on the Review page.
Query: `limit` (default 10, max 50).

Response `200`: `{"items": [...]}`. Each item is a review history entry (as above) plus
`contract_id`, `contract_name` and `label` (the field label, or the obligation description).
